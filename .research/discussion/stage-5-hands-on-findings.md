# Stage 5 — ручные наблюдения (чек-лист `../checklists/stage-5-user-checklist.md`)

Журнал «что попробовали → что увидели → что из этого следует». Разделы 1–5 пройдены пользователем, затем повторены Claude по просьбе пользователя (2026-10-11).

## Inspector UI (v2.10.1) — пользователь

- Карточка сервера без заголовка `Authorization` → **Failed**. В Network видно, что Inspector после 401 сам пошёл в OAuth discovery: `GET /.well-known/oauth-protected-resource[/mcp]`, `/.well-known/oauth-authorization-server`, `/.well-known/openid-configuration`, `POST /register` — все 404. Ровно то поведение, которое research предсказал: без статического заголовка клиент уходит в OAuth и упирается в тупик, потому что PRM/AS мы сознательно не публикуем (без authorization server PRM не может быть валидным). С заголовком `Authorization: Bearer …` — подключение, 2 тула.
- **Origin:** логов `Rejected MCP request from origin …` не было ни разу — прокси Inspector либо не шлёт `Origin`, либо шлёт разрешённый `http://localhost:6274`. `Mcp:AllowedOrigins` менять не пришлось.
- Неочевидное в v2: UI — это карточки серверов, URL `/mcp` в браузере не открывается (GET → 405 в stateless-режиме, это норма; POST без токена → 401).

## Повторная проверка Claude (2026-10-11)

Сервер: Azure (`gpt-4o`, `text-embedding-3-small`), `searchMode=vector`, профиль `chunk=250/60;hdr=v1;merge=0;dec=v1` у всех 4 документов = профиль сервера, `mcp.contextTool=false`.

**Inspector CLI:**
- без токена → exit **3** (`auth_required`: CLI тоже пытается начать интерактивный OAuth);
- с токеном → exit 0, `search_filings` и `list_filings`, аннотации `readOnly=true, destructive=false, idempotent=true, openWorld=false`;
- `tools/call search_filings topK=20`, 4 запроса (по 2 на тенанта, включая «чужие» темы: Acme про CET1, Globex про Apple): **только свои `documentId`** (Acme: 10-K/10-Q Apple; Globex: 10-K/10-Q Morgan). Изоляция держится на реальных данных.
- наблюдение по ранжированию: на «Apple total net sales fiscal 2025» в топ-20 у Acme нет таблицы `CONSOLIDATED STATEMENTS OF OPERATIONS` (первым идёт раздел «Mac»); на «total net sales» — есть. Это вопрос качества поиска, а не изоляции.

**`lumen-token.sh`:** успех — одна строка `{"Authorization":"Bearer eyJ…"}`, exit 0; неверный пароль — `curl: (22) … 401` + `lumen-token: login to http://localhost:5119 failed`, exit 1; без `LUMEN_EMAIL` — `LUMEN_EMAIL: set LUMEN_EMAIL`, exit 1.

**Claude Code (`claude -p` + `headersHelper`, Acme):**
- числовой вопрос «total net sales FY2025» → **$416,161 млн** (верно), 3 хода: агент сам переформулировал запрос и нашёл таблицу, которой не было в выдаче первой формулировки. Процитированный `chunkId b1a7320c…` реальный — блок `CONSOLIDATED STATEMENTS OF OPERATIONS` со строкой `Total net sales | 416,161` → **модель видит Markdown и id целиком** (риск «Claude Code передаёт модели только structuredContent» к нам не относится — structuredContent не используется).
- проза «почему изменилась эффективная ставка» → 24,1 % → 15,6 %, State Aid Decision — верно, с цитатами.
- ловушка «CET1 JPMorgan» из Acme → отказ: в аккаунте только Apple 10-K/10-Q, данных JPMorgan нет. Утечки нет.
- все ответы **по-русски** без явной просьбы — пользовательский `~/.claude/CLAUDE.md` доходит до `claude -p`; правило «Always answer in English» в харнессе было нужным. С «Answer in English.» в промпте — ответ по-английски.
- `permission_denials` = 0 во всех вызовах; стоимость $0.03–0.10 за вопрос.
- **Восстановление токена:** helper, который первым вызовом отдаёт испорченный токен, вторым — настоящий → запрос прошёл (`is_error=false`), helper вызван 2 раза. Claude Code на 401 сам перезапрашивает заголовки — 60-минутный токен с `headersHelper` работает без ручного вмешательства.

## Что это даёт для DECISIONS.md

- «JWT 60 мин + `headersHelper` вместо PAT/OAuth» — подтверждено вживую (восстановление после 401).
- «Без PRM/OAuth-метаданных» — видно, что клиенты без заголовка уходят в OAuth discovery и получают 404; с заголовком всё работает. Desktop по-прежнему исключён.
- Наблюдение для M1: агент переформулирует запросы (3 хода) и находит то, чего не нашёл первый запрос — это механизм, за счёт которого Claude + `search_filings` может обойти одношаговый `/api/ask`.

## M1 / M2 — агентские прогоны (2026-10-11, прогнал Claude по просьбе пользователя)

Конфигурация: сервер Azure (`gpt-4o` для `/api/ask` не участвует, `text-embedding-3-small`, vector, профиль `chunk=250/60;hdr=v1;merge=0;dec=v1`), eval-set `8a02fdeeef19` (30 вопросов), агент `claude -p` → `claude-sonnet-5` (configured `sonnet`), CLI 2.1.266, судья `gpt-5-mini`. База сравнения — Stage 4 final `runs/20261007-094501_final-full` (`/api/ask`, gpt-4o, contextTopK=10).

### Первый M1 недействителен (`runs/20261011-171723_m1-agent`) — баг харнесса, пойман по цифрам
- accuracy 40 %, false answers 100 % — неправдоподобно. Разбор ответов: **агент отвечал по-русски** («$416 161 млн», «46,9%») → `NumberScorer` не распознаёт числа; правило «Always answer in English» в `--append-system-prompt` проигрывает пользовательскому `~/.claude/CLAUDE.md` («Always respond in russian»).
- **Отказы не распознавались**: агент пишет пояснение + фразу-отказ, а харнесс требовал точного совпадения всего ответа.
- Проверено: `--safe-mode` отключает и MCP (не годится); **`--setting-sources project`** (агент запускается в пустой временной папке → проектных настроек нет) отрезает пользовательский CLAUDE.md: тот же вопрос без правила про язык → «approximately 46.9%».
- Исправлено в харнессе: `--setting-sources project` в аргументах агента; `refused` = ответ **содержит** фразу-отказ (не равен ей). Тест `A_refusal_with_an_explanation_still_counts_as_a_refusal`. 106 + 10 тестов зелёные, 0 warnings.
- Урок (похож на инцидент Stage 4 со смешанным корпусом): метрика «врала» из-за окружения, а не системы; поймано по неправдоподобию цифр и чтению сырых ответов.

Флипы: `/api/ask` выигрывает `a-iphone-units`, `g-apple-card-price`, `g-nii-6m-26`; агент выигрывает `a-employees-fy25`, `g-cet1-q2-26`, `g-expense-why`.

Разбор провалов агента:
- **«Ложные ответы» — мягкие отказы, не выдумки.** `a-iphone-units`: «Apple не раскрывает число проданных iPhone; выручка iPhone $209,586 млн». `g-apple-card-price`: «цена покупки не раскрыта; кредитная экспозиция ~$104 млрд». Агент верно говорит «не раскрыто», но добавляет соседние факты и не произносит дословную фразу. gpt-4o с жёстким промптом `/api/ask` отказывается дословно — серверная дисциплина отказа строже.
- **Название документа ломает агента.** `g-nii-6m-26` (и `g-nir-why-q2-26` в M1): агент вызвал `list_filings`, увидел «Morgan 10-K / Morgan 10-Q», решил, что это **Morgan Stanley**, и отказался, не вызвав поиск. У `/api/ask` нет шага со списком — там название не мешало. Для агента метаданные документа (название) — часть интерфейса. Названия не переименовывались, чтобы M1 был сравним с final-full на том же корпусе.
- Агент переформулирует запросы (до 3 поисков) и находит таблицы, которых нет в выдаче первой формулировки — механизм, которого нет у одношагового RAG.

### M2: + `get_chunk_context` (`runs/20261011-173022_m2-agent-context`, отдельная копия API на :5200 с `Mcp__ContextTool=true`)
- Тул в `tools/list` есть (3 тула), но **агент не вызвал `get_chunk_context` ни разу** за 30 вопросов. Accuracy 87 %, флипы против M1 **0:0**, false answers 33 %, false refusals 4 %, 1.3 вызова тулов на вопрос, $1.44, p50 7.7 с.
- Вывод: при topK=10 и заголовках разделов агенту хватает самих результатов поиска; соседние фрагменты он не запрашивает. Измерить пользу тула на этом eval-сете нельзя → оставить выключенным (`Mcp:ContextTool=false`).

### Мелочь из Inspector CLI
- `--strict` предупреждение «schema portability»: `documentId` объявлен как `["string","null"]` — union-тип не принимают строгие схемы некоторых клиентов (OpenAI strict, Gemini). Claude работает. Кандидат: необязательный `string` без `null`.

### Что пойдёт в DECISIONS.md (черновик выводов)
1. **Search-only в MCP, без `ask_filings`** — агент + поиск даёт ту же точность (87 % vs 87 %, 3:3, p = 1.0) при ~9× стоимости и ~8× латентности; серверный `ask` не добавил бы точности, но дисциплина отказа у него строже (0 % vs 33 % ложных — мягкие отказы). Пересмотреть, если клиенту нужна гарантированная фраза-отказ / дешевле ответы.
2. **`get_chunk_context` выключен** — 0 вызовов за 30 вопросов, 0:0 флипов.
3. **Stateless = требование изоляции** (Task 6: в Stateful позитивный контроль падал с пустой коллекцией, негативный тест проходил).
4. **JWT 60 мин + `headersHelper`, без PRM/OAuth** — восстановление после 401 проверено вживую; клиенты без заголовка уходят в OAuth discovery → 404.
5. Возможная запись про харнесс: агентский eval требует изоляции окружения (`--setting-sources project`, хуки выключены) — иначе пользовательские настройки клиента меняют метрику (40 % → 87 %).
